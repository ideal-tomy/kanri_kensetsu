## 3. 機能詳細

### A. 基盤機能

#### A-01 認証・ユーザー管理

**目的**：会社単位で利用者を管理し、現場ごとの参加権限を制御する。

**主要機能**
- 会社コード + メール + パスワードでログイン
- 招待コード（6桁）による現場参加（職人さんはメール不要で参加可）
- 権限：`admin` / `supervisor` / `worker` / `viewer`
- パスワード再設定（メール）／ログイン状態7日間保持

**画面**
- ログイン画面 / 招待コード入力画面 / プロフィール編集

**データ**
```
users(id, company_id, name, email, phone, role, password_hash, last_login_at)
invitations(code, site_id, role, expires_at, used_by)
```

**API**
- `POST /api/auth/login`
- `POST /api/auth/invite` （招待コード発行）
- `POST /api/auth/join` （招待コード使用）

---

#### A-02 現場マスタ

**目的**：すべての機能の起点となる「現場」を定義・管理する。

**主要機能**
- 現場の作成・編集・アーカイブ
- 基本情報：現場名 / 住所 / 工期 / 元請 / 担当監督
- 参加メンバーの追加・削除（招待コードまたは直接追加）
- 現場のステータス：`予定` / `進行中` / `完了` / `アーカイブ`

**画面**
- 現場一覧（カード型）／現場作成フォーム／現場設定

**データ**
```
sites(id, company_id, name, address, started_at, ended_at, status, supervisor_id)
site_members(site_id, user_id, role, joined_at)
```

---

#### A-03 通知

**目的**：重要な変更を見逃さない。プッシュ通知でリアルタイムに把握。

**通知トリガー**
- 日報送信完了 / メンション / トーク投稿 / ピン留め追加
- **進捗ステータス変更**（D-01連動）★
- **アサイン変更**（E-02連動）★
- 新規写真投稿

**配信手段**
- PWA Push（iOS 16.4+ / Android Chrome）
- アプリ内バッジ
- 重要通知はメール併送（オプション）

**設定**
- 種別ごとにON/OFF
- サイレント時間帯（夜間通知OFF）

---

### B. コミュニケーション機能

#### B-01 トーク（現場別チャット）

**目的**：現場ごとにグループトークを分離し、「どの現場の話？」を消す。LINE等の私用ツール代替。

**主要機能**
- 現場単位のグループトーク
- テキスト・写真・PDF・位置情報・音声メモを投稿
- ピン留め（最大5件／現場）
- 既読／未読、@メンション
- 投稿の検索（現場内）

**画面**
- トークタイムライン（下部固定入力欄、スワイプでピン留め）
- ピン留め一覧（画面上部に常時表示）

**データ**
```
messages(id, site_id, sender_id, body, attachments[], pinned, created_at)
message_reads(message_id, user_id, read_at)
```

---

#### B-02 掲示板

**目的**：トークに流れず、現場全員に必ず見せたい連絡を残す。

**主要機能**
- 重要連絡を投稿（既読確認付き）
- 全員の既読状況を一覧で確認可能
- 期限設定（例：本日中に確認）
- カテゴリ：安全 / 工程 / 連絡 / その他

---

#### B-03 アルバム（写真共有）

**目的**：写真を「現場・日付・タグ」で自動整理。後から探せる状態にする。

**主要機能**
- スマホカメラ直接撮影 or 既存写真アップロード
- EXIFから撮影日時・GPSを自動取得
- 自動分類軸：**現場 × 日付 × タグ**
- タグ候補：`着工前` / `施工中` / `完了` / `不具合` / `安全確認` / `検査` （カスタム追加可）
- ビュー切替：グリッド / 日付別 / タグ別
- PCからZIP一括ダウンロード

**画面**
- アルバム一覧（現場選択 → ビュー切替）
- 写真詳細（タグ編集・キャプション入力）

**データ**
```
photos(id, site_id, uploader_id, url, thumbnail_url, taken_at, gps_lat, gps_lng, tags[], caption)
```

**画像処理**
- WebP変換 + 長辺2000pxにリサイズ
- サムネは300x300、長辺1200pxの中サイズも生成
- 元データは90日後にコールドストレージ移行

### C. 報告・記録機能

#### C-01 日報（音声入力 + テンプレ自動整形） ★コア機能

**目的**：話し言葉そのままで、整った日報を1分以内に生成・送信。

**入力**
- 音声入力（Web Speech API、`lang="ja-JP"`）
- テキスト直接入力（フォールバック）
- 入力例：「今日は鉄筋3人、左官2人。午後から雨で作業中断。安全確認は完了してます」

**解析・整形（キーワードマッチング方式 / AIなし）**
- 自動マッピング項目：
  - 作業日 / 現場名 / 人員（職種別＋合計） / 作業内容
  - 作業状況（天候・中断有無） / 安全確認 / 特記事項
- 未認識項目はハイライトで手動補正

**出力・送信**
- 整形プレビュー → 「事務所へ送信」ボタン
- 該当現場の関係者全員に通知
- PDFエクスポート、過去日報のコピー作成

**画面遷移**
```
[マイクボタン押下]
  ↓ 音声入力
[テキスト確認・編集]
  ↓ 「日報生成」ボタン
[整形済み日報プレビュー]
  ↓ 「事務所へ送信」ボタン
[送信完了 + 通知配信]
```

**データ**
```
reports(id, site_id, author_id, work_date, raw_text, parsed_json, status, sent_at)
  parsed_json: { personnel: {...}, weather, status, safety_check, notes }
```

---

#### C-02 報告書

**目的**：日報以外の定型報告書（安全パトロール、検査記録、KY活動など）をテンプレ化して提出。

**主要機能**
- 会社ごとにカスタムテンプレート作成
- フィールド型：テキスト / 選択 / チェックボックス / 写真添付 / 署名
- 提出後はPDF化、関係者にメール配信

### D. 進行管理機能 ★追加

#### D-01 進捗管理（現場主導入力 + 内勤確認） ★最重要追加機能

**目的**：現場の人が判断して作業内容を入力し、進捗もそのまま入れる。内勤はそれを確認するだけ。
情報の発信源を「現場 → 内勤」に正す。

**主要機能**

**▼ 現場側（スマホ）**
- 「今日やる作業」を現場が登録（テキスト + 写真）
- 各タスクのステータスを更新：
  - `未着手` → `着手` → `中断` → `完了`
- 進捗％を入力（0/25/50/75/100の5段階タップ）
- 写真・コメントを紐付けて投稿
- 中断理由を選択（雨天 / 資材待ち / 人員不足 / その他）

**▼ 内勤側（PC）**
- 全現場の進捗を一覧表示（ダッシュボード）
- ステータス別フィルタ：`遅延` / `中断中` / `要確認`
- タスク詳細を開くと、関連写真・コメント・更新履歴がまとめて見える
- 「確認済み」ボタンで現場に既読を返す

**画面**
- **現場側**：今日のタスクカード（縦リスト）／タスク詳細／写真追加
- **内勤側**：進捗ダッシュボード（現場×ステータスのマトリクス）／タスク詳細

**データ**
```
tasks(
  id, site_id, title, description, planned_date,
  created_by, status, progress_pct,
  interrupted_reason, started_at, completed_at
)
task_updates(
  id, task_id, user_id, status_from, status_to,
  progress_pct, comment, photos[], created_at
)
```

**ステータス遷移ルール**
```
未着手 ─→ 着手 ─→ 完了
              ↓
            中断 ─→ 着手（再開）
```

**現場主導の理由（運用設計）**
- 内勤からの「指示」として降ってくるのではなく、現場が自分で書く
- 結果として、ベテランの判断ノウハウがそのままナレッジとして蓄積される（G-01に流れる）

---

#### D-02 工程管理

**目的**：複数タスクの予定と実績を時系列で俯瞰する。

**主要機能**
- ガントチャート表示（PC中心）
- 工種別の色分け、依存関係（前タスク完了→後タスク開始）
- スマホでは「今週の予定リスト」として簡易表示
- D-01の進捗データと連動

### E. 人員管理機能 ★追加

#### E-01 現場アサイン

**目的**：「明日、誰がどの現場にいるか」を全従業員が一目で把握できる。

**主要機能**
- カレンダー型のアサイン入力（管理者・監督）
- 1名が複数現場掛け持ちにも対応（午前A現場／午後B現場）
- 職種タグ（鉄筋・左官・大工・設備・電気…）
- 必要人数 vs 配置人数のギャップを自動表示（不足は赤）

**画面**
- **アサインボード**：縦軸＝日付、横軸＝現場、セルに人員カード
- **個人ビュー**：自分の予定だけ見たい現場作業員向け
- **現場ビュー**：その現場に誰が来るかだけ見たい監督向け

**データ**
```
assignments(
  id, user_id, site_id, work_date,
  shift_type (full / am / pm),
  role_tag, status (planned / confirmed / changed / cancelled),
  assigned_by, assigned_at
)
```

---

#### E-02 急な変更対応 ★

**目的**：「今日、雨で〇〇現場中止」「△△さん体調不良で配置替え」を、瞬時に全員に伝える。

**主要機能**
- 当日変更ボタン（管理者・監督）
  - 「現場中止」 → 該当アサインを一括キャンセル + 全員にプッシュ通知
  - 「人員入れ替え」 → ドラッグで別現場へ移動 + 関係者に通知
- 変更理由を選択（雨天 / 体調不良 / 急ぎの応援 / その他）
- 変更履歴を保持（誰がいつ何を変えたか）

**通知配信**
- 影響を受ける本人にプッシュ通知（最優先）
- 元の現場の監督・新しい現場の監督にも通知
- 確認した本人は「了解」ボタンを押す → 管理者画面に既読表示

**画面**
- 当日のタイムラインに変更履歴をリアルタイム表示
- 「未確認」の変更件数をホーム画面にバッジ表示

**データ**
```
assignment_changes(
  id, assignment_id, change_type,
  before_json, after_json, reason, changed_by, changed_at,
  acknowledged_by[], acknowledged_at[]
)
```

### F. 顧客管理機能

#### F-01 顧客カルテ

**目的**：工事完了後のフォローアップを漏らさない。担当者が変わっても情報が残る。

**主要機能**

### G. ナレッジ機能 ★差別化

#### G-01 横断検索

**目的**：過去の日報・写真・チャット・タスクから「この前どうした？」を即座に発掘。

**主要機能**
- 検索対象：日報 / トーク / 写真キャプション / タスク / 報告書
- 検索軸：キーワード × 現場 × 期間 × タグ × 投稿者
- 検索クエリ例：
  - 「雨天」「中断」 → 過去の対処事例
  - 「○○工法」「不具合」 → 失敗事例とリカバリ方法
- 検索結果カードに「類似事例」リンク（将来AI拡張）

**技術**
- PostgreSQL `tsvector` + `pg_trgm` で日本語全文検索
- 投稿時に `search_index` テーブルへ自動登録（トリガー）

**データ**
```
search_index(entity_type, entity_id, site_id, tsv, text_excerpt, created_at)
```

#### G-02 月次レポート自動生成（運用コンサル領域）

**目的**：月額50,000円の「正体」。蓄積データから資産になるレポートを納品。

**納品物（PDF）**
- 今月のヒヤリハット集（中断理由・不具合タグの抽出）
- ベテランの段取り集（高評価された日報・タスク更新の抜粋）
- 人員稼働サマリ（現場×職種×時間）
- 利用状況（投稿数・アクティブ率・詰まりポイント）

**生成プロセス**
- 自動抽出 → 運用担当（弊社）が補足コメント追記 → 顧客へPDF納品
- 月次の改善定例（30分／オンライン）の議題に使用

## 9. UI/UX原則（職人さん向け再掲）

1. **ボタンは指1本でデカく** - タップ領域60px以上、漢字+アイコン
2. **入力は音声 or 選択** - テキスト打鍵を極力させない
3. **1画面1機能・2タップ以内** - メニュー階層を作らない
4. **進捗・アサインは "色"で即判断** - 文字を読まなくてもわかる
   - 緑＝順調 / 黄＝注意 / 赤＝遅延・中断 / 青＝完了 / 灰＝未着手
5. **急変更は最優先表示** - ホームに大きな赤いカードでバッジ表示
