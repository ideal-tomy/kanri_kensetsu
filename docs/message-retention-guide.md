# トーク（チャット）ログの保管ポリシー

実装指示書 §2.2 に基づく、メッセージの保管階層と運用上の注意です。

## 保管の3階層（概要）

| 階層 | 期間の目安 | 保存先 | 備考 |
|------|------------|--------|------|
| HOT | 直近（既定 30 日） | PostgreSQL（`messages`） | 一覧・検索・リアルタイム反映 |
| WARM | 中期（既定 31〜90 日） | Object Storage（gzip JSON） | コスト削減のため DB から退避 |
| COLD | 長期（91 日以降） | 削除または別ストレージ | 会社ポリシーに応じて |

## 設定項目（`message_retention_policies`）

- **hot_days**: DB に置いておく日数（既定 30）
- **warm_days**: WARM 層に残す期間の上限（既定 90）
- **delete_after**: 完全削除までの日数（未設定なら削除しない運用も可）

## 例外（常に残す）

- **ピン留め**（現場あたり最大 5 件）
- **重要マーク**付きメッセージ

これらは HOT/WARM の移動・削除対象から除外します。

## 自動アーカイブ

日次ジョブ（Supabase Edge Function 等）で HOT 期間を超えた通常メッセージを gzip で `message-archives` バケットへ退避し、DB から削除します。

## 利用者向け説明（短文）

「最近のやり取りはアプリですぐ見られます。古い分は会社の保存期間に従い自動でまとめて保管され、ピン留めした大事な連絡だけはいつでも残ります。」
