# 実務担当者 指示書 v2.0｜ロール別UI分離

> **このファイルの位置づけ**
> v1.0で「機能追加とUI/UX改善」を行った後、**ロールごとに見える画面を分ける**ための大規模改修指示書。これによりGENBA NOTEは「現場モード」「管理モード」の2世界に分かれる。
> 既存ファイル：`Cursor指示書_v1.0.md` `機能仕様書_v2.0.md` `Claude_Code指示書_v1.0.md` を前提に進める。

## 0. なぜロール分離するのか

### 0.1 現状の問題

現状（v1.1時点）は **全員に全機能を見せている**。これは以下の問題を生む：

- 田中さん（55歳・老眼の職人）視点では、「現場ぜんたい42%」「ナレッジ検索」など自分に関係ない情報が並び、画面が複雑に見える
- 自分に関係ない項目をうっかりタップして誤操作の原因になる
- 「IT嫌い」を再生産し、定着しない

### 0.2 解決の方向性

**1つのアプリを、URLで2世界に分ける**

```
genba-note.app/
├── /m/*       … 現場モード（スマホ専用設計）
│               職人・現場監督が使う
│
└── /admin/*   … 管理モード（PC優先 + スマホ閲覧）
                内勤・経営者が使う
```

ログイン時にロールに応じて自動で正しい世界に飛ばす。

### 0.3 3ロール × 2モードの対応表

| ロール | デフォルトURL | 主な使い方 | 端末 |
|--------|--------------|-----------|------|
| `worker`（職人） | `/m/worker` | 超シンプル4画面 | スマホ専用 |
| `supervisor`（現場監督） | `/m/supervisor` | スマホだが機能多め | スマホ中心 |
| `admin`（内勤） | `/admin` | フル機能ダッシュボード | PC優先 |
| `owner`（経営者） | `/admin/dashboard` | サマリと月次レポ閲覧 | PC・スマホ閲覧 |

> **重要**：URLは固定だが、ユーザーがロール権限の範囲内で別URLにアクセスするのは禁止しない。たとえば監督が `/admin` にアクセスすれば「権限がありません」と弾く（後述§4のミドルウェア）。

```typescript
import { redirect } from 'next/navigation';
import { getCurrentUser } from '@/lib/auth';

export default async function RootPage() {
  const user = await getCurrentUser();
  if (!user) redirect('/login');

  switch (user.role) {

    case 'admin':
    case 'owner':      redirect('/admin');
```

## 4. 認証・権限制御の実装

### 4.1 ミドルウェアでURL保護

```typescript
// src/middleware.ts
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';
import { getUserFromRequest } from '@/lib/auth/server';

export async function middleware(req: NextRequest) {
  const path = req.nextUrl.pathname;

  // 認証不要パス
  if (path.startsWith('/login') || path.startsWith('/join') || path.startsWith('/api/auth')) {
    return NextResponse.next();
  }

  const user = await getUserFromRequest(req);
  if (!user) return NextResponse.redirect(new URL('/login', req.url));

  // 管理モード保護
  if (path.startsWith('/admin')) {
    if (!['admin', 'owner'].includes(user.role)) {
      return NextResponse.redirect(new URL('/m/worker', req.url));
    }
  }

  // 現場モード（職人）保護
  if (path.startsWith('/m/worker')) {
    // workerだけでなくsupervisorもアクセス可能（自分のホーム的に）
    // 厳密にしたいなら role !== 'worker' で弾く
  }

  // 現場モード（監督）保護
  if (path.startsWith('/m/supervisor')) {
    if (!['supervisor', 'admin', 'owner'].includes(user.role)) {
      return NextResponse.redirect(new URL('/m/worker', req.url));
    }
  }

  return NextResponse.next();
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico|icons|manifest.json).*)'],
};
```

### 4.2 ログイン後のリダイレクト


## 6. データAPIの権限フィルタ

### 6.1 ロールベースのデータ絞り込み

```typescript
// src/lib/api/sites.ts
export async function getSitesForUser(user: User) {
  if (user.role === 'worker') {
    // 職人：今日アサインされた現場のみ
    return supabase
      .from('sites')
      .select('*, assignments!inner(*)')
      .eq('assignments.user_id', user.id)
      .eq('assignments.work_date', today());
  }
  
  if (user.role === 'supervisor') {
    // 監督：自分が監督する現場 + 自分がメンバーの現場
    return supabase
      .from('sites')
      .select('*')
      .or(`supervisor_id.eq.${user.id},members.user_id.eq.${user.id}`);
  }
  
  // admin / owner：全現場
  return supabase
    .from('sites')
    .select('*')
    .eq('company_id', user.company_id);
}
```

## 8. シードデータの再整備

ロール別の動作確認のため、最低でも以下の組み合わせを用意：

```sql
-- ユーザー
-- worker × 5名（田中・佐藤・鈴木・高橋・渡辺）
-- supervisor × 2名（伊藤・山本）
-- admin × 1名（中村花子）
-- owner × 1名（山田社長）

-- 各ユーザーでログインしたとき、それぞれのデフォルトURLに正しく飛ぶことを確認
-- 田中（worker）→ /m/worker
-- 伊藤（supervisor）→ /m/supervisor
-- 中村（admin）→ /admin
-- 山田（owner）→ /admin

-- 配置データを今日（CURRENT_DATE）基準で動的生成
INSERT INTO assignments (user_id, site_id, work_date, shift)
SELECT u.id, s.id, CURRENT_DATE, 'day_full'::shift_type
FROM users u, sites s
WHERE (u.name, s.name) IN (
  ('田中太郎', 'A邸新築'),
  ('佐藤次郎', 'A邸新築'),
  ('鈴木三郎', 'Bビル改修'),  -- これは夜勤

);
```

## 11. やらないこと（スコープ外）

- 職人モードでのナレッジ検索 → admin/supervisor のみ
- 職人モードでの他人の写真閲覧 → 自分が投稿したもの + 同じ現場のもののみ

- スマホ管理モードのフル機能 → スマホでは閲覧と簡易操作のみ
