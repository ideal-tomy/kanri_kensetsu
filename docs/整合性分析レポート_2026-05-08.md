## 1. 前提：アプリのデータ層が二重になっている

本プロジェクトには **2つの独立したデータ源泉** が存在する。これが全ての不整合の根本原因。

| 層 | ファイル | 役割 | スキーマ例 |
|---|---|---|---|
| **静的モックデータ** | `src/data/mock/*.ts` | 管理ページのデモ表示用。起動時に固定。 | `ReportPhoto { projectId, uploadedByWorkerId, renamedFileName, aiConfidence }` |
| **動的インメモリストア** | `src/lib/prototype-store.ts` | ワーカー/監督が実際に書き込む。セッションで更新される。 | `PhotoReport { siteId, userName, category, fileName, title, note }` |

ワーカーが投稿した写真は **`state.photoReports`（prototype-store）** に書き込まれるが、管理ページはすべて **`data/mock/reportPhotos`** を読んでいるため、**ワーカーの実際の作業が管理画面に一切表示されない**。

## 3. ギャップ詳細：データスキーマの差異

### 写真データの型不一致

管理ページが参照している **mock `ReportPhoto`** と、ワーカーが実際に書き込む **`PhotoReport`** でフィールドが異なる。

```
mock ReportPhoto（管理ページが現在読んでいる）
  id, projectId, uploadedByWorkerId, capturedAt,
  originalFileName, renamedFileName,
  storagePath, tags, aiLabelSummary, aiConfidence

prototype-store PhotoReport（ワーカーが実際に書き込む）
  id, siteId, userName, category,   ← categoryが新フィールド
  fileName, title?,                  ← titleは進捗報告で必須
  note?, storagePath, createdAt
```

管理ページがワーカーデータを表示するには、`getPhotoReportsForUser(adminUser)` を呼んで `PhotoReport` 型で描画するよう変更が必要。

### 現場IDの二重管理

```
data/mock/projects: id = "p1", "p2", "p3" ...
prototype-store sites: id = "site-1", "site-2", "site-3" ...
```

`/admin/projects/[id]` は `p1` などのIDでルーティングされており、`state.tasks`（siteId = "site-1"）とは紐づかない。直接マッピングは不可。

## 6. 実装時の注意点

### セッション取得（Server Component用）
管理ページでprototype-storeを読むには、Server Componentで管理者セッションを取得する必要がある。`getPhotoReportsForUser` は `SessionUser` を受け取る設計になっており、`requireSession` + role確認で実装可能。

ただし現状 `requireSession` はcookieベースで、adminページはSession非依存で動作している部分がある。admin用のServer Component向けセッション取得ヘルパーが必要になる場合がある。

### PhotoReport表示の型対応
管理ページが現在 `ReportPhoto`（mock型）を前提としているため、`PhotoReport`（prototype-store型）に切り替える際はコンポーネント側の型定義も更新が必要。

```ts
// prototype-store PhotoReport
type PhotoReport = {
  id: string;
  siteId: string;
  userName: string;
  category: "regular" | "progress";
  fileName: string;
  title?: string;      // 進捗報告のみ
  note?: string;
  storagePath: string;
  createdAt: string;
};
```

### カテゴリラベルの統一
管理ページにもワーカーページと同じラベルを使うこと。

```ts
const CATEGORY_LABEL = {
  regular: "定例報告",
  progress: "進捗報告",
};
```
