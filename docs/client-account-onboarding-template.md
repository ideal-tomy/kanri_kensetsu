# GENBA NOTE 導入時アカウント準備・代行同意書（テンプレ）

本書は、GENBA NOTE の導入にあたり、開発環境から運用環境までに必要なアカウント作成と初期設定を円滑に進めるための確認書です。  
IT運用負荷とコストを抑えることを目的に、最小構成で開始します。

---

## 1. 方針（低コスト運用）

- 新規ドメイン取得は原則行わず、既存ドメインのサブドメインを利用します  
  （例: `genba.example.co.jp`）。
- ストレージは `Supabase Storage` を使用します（他ストレージは利用しません）。
- 初期構成は以下の最小セットとします。
  - `Supabase`（DB / Auth / Storage / Realtime）
  - `Vercel`（ホスティング）
  - `Sentry`（任意・推奨、障害監視）

---

## 2. アカウント作成の役割分担

### 貴社にご対応いただく内容

- 共通管理用メールアドレスの作成（2つ）
  - `genbanote-owner@<貴社ドメイン>`
  - `genbanote-ops@<貴社ドメイン>`
- 既存ドメイン管理画面（DNS）の変更承認
- 各サービスの利用規約・請求条件の確認および承認
- 必要に応じた2段階認証コードの共有（初回設定時のみ）

### 当方で代行する内容（ご承認後）

- Supabase / Vercel / Sentry のアカウント作成、初期設定
- プロジェクト作成、環境変数設定、デプロイ設定
- DNS設定の具体値提示と疎通確認
- 初期の権限設計（運用者・閲覧者）
- 設定完了後の引き渡し資料作成

---

## 3. 代行同意（ひな形）

以下の内容に同意のうえ、当方へ初期設定作業を委託します。

1. 各サービスの契約主体・オーナーは貴社とする。  
2. 当方は初期構築のために管理者権限を一時的に保持する。  
3. 本番稼働後は、貴社オーナー権限の確認を行い、当方権限を運用に必要な最小権限へ変更する。  
4. パスワードは平文共有せず、必要時は貴社側で再設定を実施する。  
5. 2段階認証を有効化し、復旧コードは貴社にて安全に保管する。  
6. 料金発生サービスの請求先は貴社名義とし、当方は請求情報を保持しない。

## 5. 初期設定チェックリスト（開発〜運用）

## 5-1. 事前準備（貴社）

- [ ] 共通管理用メール2つを作成した
- [ ] 既存ドメイン管理者（DNS変更可能者）を確定した
- [ ] 請求用の法人カードまたは支払い手段を準備した
- [ ] 代行同意（本書）を承認した

## 5-2. アカウント作成（当方代行）

- [ ] `Supabase` に `genbanote-owner` で登録
- [ ] `Vercel` に `genbanote-owner` で登録
- [ ] `Sentry`（利用時）に `genbanote-owner` で登録
- [ ] `genbanote-ops` を運用連絡先として追加
- [ ] すべてで2段階認証を有効化

## 5-3. 開発環境

- [ ] Supabase プロジェクト（dev）作成
- [ ] 必要テーブル・RLS・Storageバケットを適用
- [ ] Vercel プロジェクト（dev）作成
- [ ] Vercel 環境変数（Supabase URL/Key等）設定
- [ ] 動作確認用URLでアクセス確認

## 5-4. 本番環境

- [ ] Supabase プロジェクト（prod）作成
- [ ] Vercel プロジェクト（prod）または本番ブランチ設定
- [ ] 本番環境変数を分離設定（devと混在させない）
- [ ] 既存ドメインのサブドメインをVercelへ割当
- [ ] DNS反映後、HTTPS証明書と疎通を確認

## 5-5. 引き渡し

- [ ] 貴社担当をOwnerとして最終確認
- [ ] 当方権限を必要最小限へ変更
- [ ] 復旧コード保管場所を確認
- [ ] アカウント一覧・権限一覧・運用手順を納品
- [ ] 緊急連絡フロー（障害時）を共有

---

## 6. コスト最適化メモ（運用方針）

- 開始時は最小プランで開始し、利用実績に応じて段階的に上位化する  
  （初期から過剰スペックを契約しない）。
- 監視はまずSentryの基本機能で運用し、必要時のみ拡張する。
- 新規ドメインは原則不要。既存ドメイン活用で固定費を増やさない。
- ストレージは Supabase Storage に統一し、構成の複雑化を避ける。
