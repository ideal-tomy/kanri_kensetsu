## 1. 現状把握（スクリーンショットから読み取れる課題）

### 1.1 確認した画面

- `/` ホーム（現場一覧）
- `/reports` 日報を書く
- `/tasks` 今日のしごと（進捗）
- `/personnel` だれでも見れる人員ボード
- `/search` 探す（ナレッジ検索）

### 1.2 現状の良い点

- 文言ポリシーは概ね守られている（「マイクで話す」「事務所に送る」「やってる/とまってる」など）
- ボタンは大きく、3色（緑=着手・赤=中断・青=完了）で意味が明確
- 下部ナビ5タブで主要機能に2タップ以内
- 骨格は機能仕様書に沿っている

### 1.3 改善が必要な点（スクリーンショット分析）

| 画面 | 現状の問題 | 改善方針 |
|------|----------|---------|
| ホーム | 「じょうたい: 進行中」と英語混じりの表記。情報が薄い | 各現場に「今日の出席人数」「進捗バー」「未読件数」を出す |
| 日報 | 「現場（必須）」「なまえ（必須）」と必須マーカーが冗長。「現在の現場：未選択」がIT的 | 必須は文言で。「いまの現場」削除し、現場選択を画面上部に固定 |

| 人員ボード | 「区分: full」「区分: am」と内部値がそのまま露出。日付がベタ並び | 週カレンダー型のマトリクスに作り変える。日勤/夜勤の色分け |
| 探す | デフォルトで「結果はありません」が出ているのが寂しい | 「最近よく検索されること」「タグから探す」のサジェストを表示 |

## 2. 追加機能 3点（今回の重点実装）

### 2.1 機能①：出来高（進捗の数値管理）

#### コンセプト
「鉄筋組み 50%」だけでは伝わらない。**「壁35枚中18枚完了（51%）」**のように、現場で使う単位そのままで管理する。% は自動計算。

#### UI仕様

**タスク作成時に追加する入力欄**

```
[しごと名]：例「外壁ボード貼り」
[たんい]：枚 / m² / 本 / m / 箇所 / ㎥ / その他（自由入力）
[予定数]：例「35」
[今日やる予定]：例「12」（オプション）
```

**タスクカード表示**

```
┌─────────────────────────┐
│ 外壁ボード貼り             │
│ ━━━━━━━━━━━━━━━━━━━     │
│ 18 / 35 枚（51%）          │
│ ▓▓▓▓▓▓▓▓▓▓░░░░░░░░░ 51% │
│                            │
│ [着手] [中断] [完了]       │
│ [+1] [+5] [数値で入れる]   │ ← NEW
└─────────────────────────┘
```

**入力UIのポイント**

- `[+1]` `[+5]` `[+10]` のクイック加算ボタン（よく使う数値）
- 「数値で入れる」をタップで数字パッド表示（カスタム）
- ロングタップで `−1` `−5` の減算もできる
- 完了したら自動的に `実績数 = 予定数` にセット
- 進捗バーは色のグラデーション：
  - 0–30%：青
  - 30–70%：オレンジ
  - 70–99%：黄緑
  - 100%：緑

#### DB拡張

```sql
ALTER TABLE tasks ADD COLUMN unit TEXT;          -- '枚' / 'm²' / '本' / 'm' / '箇所' / '㎥'
ALTER TABLE tasks ADD COLUMN planned_qty NUMERIC;
ALTER TABLE tasks ADD COLUMN actual_qty NUMERIC DEFAULT 0;
ALTER TABLE tasks ADD COLUMN today_target_qty NUMERIC;

ALTER TABLE task_updates ADD COLUMN qty_delta NUMERIC;  -- このupdateで加算した数
ALTER TABLE task_updates ADD COLUMN qty_after NUMERIC;  -- update後の累計
```

`progress_pct` は `actual_qty / planned_qty * 100` で**算出値として扱う**（DBには保存するが、書き込みは自動）。

#### 単位マスタ（プリセット）

```typescript
// src/lib/constants/units.ts
export const UNIT_PRESETS = [
  { value: '枚', label: '枚', step: 1 },
  { value: 'm²', label: '㎡', step: 1 },
  { value: '本', label: '本', step: 1 },
  { value: 'm', label: 'm', step: 0.5 },
  { value: '箇所', label: '箇所', step: 1 },
  { value: '㎥', label: '㎥', step: 0.5 },
  { value: '個', label: '個', step: 1 },
  { value: 'kg', label: 'kg', step: 1 },
] as const;
// それ以外は自由入力
```

### 2.2 機能②：週カレンダー型 人員配置（でづら）

#### コンセプト
現状の人員ボード（タスク的な縦リスト）を、**1週間×現場のマトリクス**に作り替える。
「人員管理者が個別連絡で配ってた」業務を **「全員が同じカレンダーを見て分かる」** 形にする。

#### UI仕様

##### A. 週カレンダー本体（PC・タブレット中心）

```
┌─────────────────────────────────────────────────────────────────┐
│ でづら表（人員配置） │ < 先週 │ 今週 5/8〜5/14 │ 来週 > │ [新しく配置] │
├──────────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┤
│ 現場名     │ 月  │ 火  │ 水  │ 木  │ 金  │ 土  │ 日  │
├──────────┼─────┼─────┼─────┼─────┼─────┼─────┼─────┤
│ A邸新築    │田中☀│田中☀│ 雨予│田中☀│田中☀│ ・ │ ・ │
│            │佐藤☀│佐藤☀│ 中止│佐藤☀│     │     │     │
├──────────┼─────┼─────┼─────┼─────┼─────┼─────┼─────┤
│ Bビル改修  │鈴木🌙│鈴木🌙│鈴木🌙│ ・ │鈴木🌙│鈴木🌙│ ・ │
│            │ 夜勤 │ 夜勤 │ 夜勤 │     │ 夜勤 │ 夜勤 │     │
├──────────┼─────┼─────┼─────┼─────┼─────┼─────┼─────┤
│ Cマンション│ ・ │ 山田☀│ 山田☀│ 山田☀│ 山田☀│ ・ │ ・ │
└──────────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
☀ = 日勤  🌙 = 夜勤
```

**操作仕様**
- セルをクリック → 「この日この現場に人を追加」モーダル
- 人員アイコンをドラッグ → 別現場・別日付に移動
- 当日変更は赤い枠で強調 + 関係者にプッシュ通知
- 雨で中止になった日はセル全体が赤くスラッシュ表示
- 1セルに複数人が入る（縦に重なる）

##### B. 個人ビュー（スマホ・本人用）

```
┌─────────────────────────┐
│ 田中さんの今週            │
├─────────────────────────┤
│ 月 5/8  A邸新築 ☀ 日勤    │
│ 火 5/9  A邸新築 ☀ 日勤    │
│ 水 5/10 ❌ 雨で中止       │
│ 木 5/11 A邸新築 ☀ 日勤    │
│ 金 5/12 A邸新築 ☀ 日勤    │
│ 土 5/13 ・ 休み           │
│ 日 5/14 ・ 休み           │
└─────────────────────────┘
```

##### C. 現場ビュー（監督・本社用）

その現場に、今週誰が来るかだけが見える縦リスト。

#### 表示ルール

- **日勤** ☀ オレンジ
- **夜勤** 🌙 ネイビー（背景色も濃い）
- **半日（午前/午後）** 半分の塗り
- **休み・未配置** グレー or 空白
- **当日変更あり** 赤い枠で点滅

#### DB拡張

`shift_type` ENUM を以下に変更：

```sql
-- 既存
-- CREATE TYPE shift_type AS ENUM ('full', 'am', 'pm');

-- 変更後
DROP TYPE IF EXISTS shift_type CASCADE;
CREATE TYPE shift_type AS ENUM (
  'day_full',    -- 日勤・1日
  'day_am',      -- 日勤・午前のみ
  'day_pm',      -- 日勤・午後のみ
  'night_full',  -- 夜勤・1晩
  'night_early', -- 夜勤・前半
  'night_late'   -- 夜勤・後半
);
```

**注意**：既存データの移行が必要なら、`'full' → 'day_full'` のマッピングで移行する。

### 2.3 機能③：現場全体の進捗（手動入力）

#### コンセプト
「日々のタスク（D-01）」とは独立して、現場全体の進捗を監督が手動で入れる。
タスクの集計とは連動させない（要件確定済み）。

#### UI仕様

**現場ダッシュボードに常時表示**

```
┌────────────────────────────────┐
│ A邸新築                          │
│ 着工 2026-04-01 ／ 引渡 2026-08-31│
│                                  │
│ 全体の進捗                       │
│ ▓▓▓▓▓▓▓▓░░░░░░░░░░░░░ 42%   │
│ [変更する]                       │
│                                  │
│ 今日のしごと（タスク）           │
│ ・外壁ボード貼り 18/35枚         │
│ ・足場点検 とまってる             │
│ ・型枠調整 やってる              │
└────────────────────────────────┘
```

**変更モーダル**

```
┌─────────────────────────┐
│ 現場全体の進捗を変える     │
├─────────────────────────┤
│ いま：42%                  │
│                            │
│ [40] [45] [50] [55] [60]   │ ← クイック選択
│                            │
│ または数字で入力：         │
│ [    ] %                   │
│                            │
│ ひとこと（任意）：         │
│ [基礎工事完了。来週から…]  │
│                            │
│ [やめる] [これでOK]        │
└─────────────────────────┘
```

#### DB拡張

```sql
ALTER TABLE sites ADD COLUMN overall_progress INTEGER DEFAULT 0
  CHECK (overall_progress BETWEEN 0 AND 100);

CREATE TABLE site_progress_logs (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  site_id UUID NOT NULL REFERENCES sites(id) ON DELETE CASCADE,
  user_id UUID NOT NULL REFERENCES users(id),
  progress_from INTEGER,
  progress_to INTEGER NOT NULL,
  comment TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

ログをとっておくことで、後で「2ヶ月で30% → 60%に進んだ」のような月次レポートに使える。

## 3. UI/UX 改善タスク（既存画面）

> 順番にこなす。各タスク完了時はスクショを撮ってBefore/Afterで確認。

### 3.1 ホーム画面

**Before**：現場名 + 「じょうたい: 進行中」 + 2ボタンだけ
**After**：

```
┌────────────────────────────────┐
│ A邸新築                  3 ●未読 │
│ 進行中 ／ 全体 42%              │
│ ▓▓▓▓▓▓▓▓░░░░░░░░░░░░ 42%    │
│                                 │
│ 今日いる人：田中・佐藤            │
│                                 │
│ [日報を見る] [今日のしごと]      │
└────────────────────────────────┘
```

**実装ポイント**
- 「じょうたい:」表記をやめ、ステータスを単独で表示
- 進捗バー追加（site.overall_progress を表示）
- 未読バッジ（messages の unread count）
- 今日の出席者（assignments の今日のレコード）
- ボタンも「日報を見る」「今日のしごと」など具体的に

### 3.2 日報画面

**Before**：必須マーカーが冗長。「現在の現場：未選択」が表示
**After**：
- 「現場」「なまえ」のラベルをシンプルに（必須は赤色の小さなドット）
- 「現在の現場：未選択」の行を削除（選択済みなら現場名を画面上部にバッジ表示）
- マイクボタンは画面下部に固定（スクロールしても消えない）
- 入力後すぐ「これで送る」→ プレビュー → 「送る」のフロー

### 3.3 進捗画面

**Before**：タスクカードに3つのステータスボタンだけ
**After**：
- 出来高（数値）入力エリア追加（§2.1）
- ステータス変更時にカードがアニメーションで色変化
- 「中断」を選んだら、理由選択モーダル（雨/材料まち/人手たりない/そのほか）
- 完了したら花火っぽい小さな祝福アニメ（職人さんの達成感）

### 3.4 人員ボード（最重要）

**Before**：縦リスト型
**After**：§2.2 の週カレンダー型に作り変え

**実装の優先順位**
1. PC用の週カレンダーマトリクス
2. 個人ビュー（スマホ）
3. 急変更ボタン
4. ドラッグ&ドロップ移動

### 3.5 探す画面

**Before**：空欄
**After**：
- 検索バーの下に「よく探されてる」サジェストを表示
  - 「雨天対応」「中断」「不具合」「やり直し」など
- タグ一覧から絞り込み（チップUI）
- 結果は日報・チャット・写真を混ぜて時系列で表示

## 4. 実装の進め方（実装担当者への作業指示）

### 4.1 作業ブランチ戦略

```bash
git checkout -b feature/v1.1-improvements
```

各機能ごとにコミットを分ける：
- `feat: 出来高（数値進捗）入力UI`
- `feat: 週カレンダー型 人員配置`
- `feat: 現場全体進捗の手動入力`
- `refactor: ホーム画面の情報密度UP`
- `refactor: 日報画面のラベル整理`
- `style: 探す画面にサジェスト追加`

### 4.2 実装順序（推奨）

```
1. DB拡張（§2.1, §2.2, §2.3 の ALTER TABLE 全部）
   ↓
2. テストデータ投入（§5参照）
   ↓
3. 出来高入力UI（既存tasks画面を拡張）
   ↓
4. 現場全体進捗（site画面に追加）
   ↓
5. ホーム画面リッチ化（出来高と全体進捗が両方使える）
   ↓
6. 週カレンダー（personnel画面を作り変え）
   ↓
7. 探す画面サジェスト
   ↓
8. 全体テスト＋仮ペルソナ視点での確認
```

### 4.3 各タスクの完了基準

```yaml
出来高UI:
  - [+1][+5][+10]ボタンで実績加算ができる
  - 進捗バーが色グラデーションで表示される
  - 数値入力モーダルが動く
  - DBに qty_delta が記録される

週カレンダー:
  - 月〜日 × 現場 のマトリクスが表示される
  - 日勤/夜勤がアイコンと色で区別される
  - セルクリックで人員追加モーダルが開く
  - 当日変更が赤枠で強調される
  - スマホでは個人ビューに自動切替

現場進捗:
  - sites.overall_progress を編集できる
  - クイック選択ボタン[40][45][50][55][60]が動く
  - site_progress_logs に変更履歴が残る
```
