# 運用準備マスタードキュメント v1.0｜現場ナレッジ管理ツール

> **このドキュメントの役割**
> 機能実装後、実際に運用を開始するために必要な「準備物・データ構造・テンプレート・操作手順」を1つにまとめたマスター資料。
> Cursor/Claude Codeに読み込ませて、Supabaseのテーブル作成からシードデータ投入、運用マニュアル生成まで、ここを基点に進める。
>
> **背景**
> 機能は完成しつつあるが、「何を準備すれば動くのか」が散在している。本ドキュメントで以下を統合：
> - 必要なDBテーブル全リスト
> - 各テーブルに事前登録すべき情報
> - テンプレート類（報告書フォーマット、現場画像フォルダ階層など）
> - 各画面の役割と操作方法
> - 運用開始までのチェックリスト

```

  ├─ branches（事業所）

  │    └─ user_qualifications（資格）
```

### 3.2 マスタ系テーブル（事前登録）

#### companies（会社）

```sql
CREATE TABLE companies (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  name_kana TEXT,
  company_code TEXT UNIQUE NOT NULL,        -- ログイン用：YAMADA
  representative TEXT,                       -- 代表者名
  postal_code TEXT,
  address TEXT,
  phone TEXT,
  email TEXT,
  logo_url TEXT,
  plan TEXT DEFAULT 'standard',
  contracted_at DATE,                        -- 契約開始日
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

#### branches（事業所）

```sql
CREATE TABLE branches (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id UUID NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  name TEXT NOT NULL,                        -- 札幌本社
  address TEXT,
  phone TEXT,
  is_headquarters BOOLEAN DEFAULT FALSE,     -- 本社フラグ
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

#### users（労働者）★拡張

```sql
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id UUID NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  branch_id UUID REFERENCES branches(id),
  auth_id UUID UNIQUE,                       -- Supabase Auth連携
  
  -- 基本情報
  name TEXT NOT NULL,
  name_kana TEXT,
  email TEXT,
  phone TEXT,
  
  -- 役割
  role user_role DEFAULT 'worker',           -- worker/supervisor/admin/owner
  job_tag TEXT,                              -- 鉄筋工/左官/大工/設備/電気/その他
  
  -- 雇用情報
  employment_type TEXT,                      -- 正社員/契約/パート/協力会社
  subcontractor_id UUID REFERENCES subcontractors(id),  -- 協力会社所属の場合
  hired_at DATE,                             -- 入社日
  retired_at DATE,                           -- 退職日
  
  -- 表示
  avatar_url TEXT,
  is_active BOOLEAN DEFAULT TRUE,
  
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_users_company ON users(company_id);
CREATE INDEX idx_users_active ON users(company_id, is_active);
```

### 3.3 案件・現場系テーブル

#### projects（案件）★ 新設

```sql
CREATE TYPE project_status AS ENUM (
  'planned',     -- 計画中
  'contracted',  -- 受注済み
  'active',      -- 進行中
  'completed',   -- 完了
  'archived'     -- アーカイブ
);

CREATE TABLE projects (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id UUID NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  
  -- 識別
  project_code TEXT,                         -- 自社の案件番号 P-2026-001
  name TEXT NOT NULL,                        -- A邸新築工事
  
  -- 顧客・元請
  client_id UUID REFERENCES clients(id),     -- 施主または元請
  end_client_name TEXT,                      -- 最終施主名（元請から受注時）
  
  -- 工期
  contract_date DATE,                        -- 契約日
  started_at DATE,                           -- 着工日
  ended_at DATE,                             -- 完工予定日
  actual_ended_at DATE,                      -- 実際の完工日
  
  -- 工事種別
  project_type TEXT,                         -- 新築/リフォーム/改修/解体/その他
  total_floor_area NUMERIC,                  -- 延床面積
  
  -- 金額
  contract_amount NUMERIC,                   -- 受注金額
  budget_amount NUMERIC,                     -- 原価予算
  
  -- 進捗
  status project_status DEFAULT 'planned',
  overall_progress INTEGER DEFAULT 0 CHECK (overall_progress BETWEEN 0 AND 100),
  
  -- 担当
  manager_id UUID REFERENCES users(id),      -- 案件責任者
  
  -- メモ
  notes TEXT,
  
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_projects_company_status ON projects(company_id, status);
```

```sql
  -- ストレージ
```

#### tasks（業務内容・ノルマ）

```sql
CREATE TABLE tasks (

  -- 期間
  planned_date DATE,
  
  -- ステータス

  -- タイムスタンプ
  started_at TIMESTAMPTZ,
  completed_at TIMESTAMPTZ,
  
  -- 確認
  created_by UUID NOT NULL REFERENCES users(id),
  acknowledged_by UUID REFERENCES users(id),
  acknowledged_at TIMESTAMPTZ,
  
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
```

### 6.2 ロール別操作フロー

#### 職人（worker）の1日

```
1. 朝：スマホでログイン → /m/worker
2. ホーム画面で「今日はA邸新築・8時集合・日勤」を確認
3. 「いっしょの人：佐藤さん」を確認
4. 現場到着後、定例報告で「朝礼」写真を1枚投稿
5. 作業中、進捗報告で「外壁ボード貼り」を選択
   → 写真撮影 → 状態「半分くらい」をタップ
6. 昼休み、定例報告で「昼休憩」写真
7. 午後、進捗報告で「外壁ボード貼り」更新
   → 状態「あと少し」
8. 終業前、進捗報告で「外壁ボード貼り」
   → 状態「おわった」
9. 「日報を書く」 → マイクで「今日は外壁ボード貼り完了、雨なし、安全確認OK」
10. 自動整形プレビュー → 「事務所に送る」
```

**所要時間：1日合計5分以内**

#### 監督（supervisor）の1日

```
1. 朝：スマホで /m/supervisor → 担当2現場の状況を確認
2. 各現場の「今日の人員」「進捗」を確認
3. 必要に応じて職人に電話・チャットで指示
4. 昼：定期的に /m/supervisor/photo で写真をチェック
5. 進捗報告で職人が「半分くらい」と入れた数値を、
   /m/supervisor/tasks で「18/35枚」に補正
6. 夕：日報がまだ来てない職人に催促
7. 夜：明日の段取り確認、必要なら内勤に人員調整依頼
```

**所要時間：1日合計30分**

#### 内勤（admin）の1日

```
1. 朝8時：PCで /admin にログイン
2. ダッシュボードで全現場の状況確認
3. 「急ぎの対応」アラートを処理
   - 日報未提出 → 監督に確認
   - 天気予報雨 → 該当現場の段取り確認
4. /admin/assignments で当日の人員配置を最終確認
   - 急な欠勤あれば → ドラッグで別現場へ移動
   - 関係者にプッシュ通知が自動配信
5. /admin/field-reports で写真投稿を確認
   - 不具合タグの写真があれば監督・社長に報告
6. 月末は /admin/reports で報告書を一括PDF出力 → 元請に提出
```

**所要時間：朝30分・夕方30分**

#### 経営（owner）の1週間

```
1. 月初：先月のナレッジレポートPDFを読む（自動納品）
2. 週始：/admin で全現場の進捗をひと目で確認
3. 週中：気になる現場の写真を /admin/reports/photos で見る
4. 週末：/admin/projects で案件別の収支を確認
```

### 6.3 操作で困ったときの対応表

| 困りごと | 解決方法 |
|---------|---------|
| 音声入力が動かない | iPhoneは「マイクの権限」を許可。Android Chromeは最新版に |
| 写真が大きすぎてアップできない | 自動でリサイズされるはず。1分以上かかる場合は通信環境を確認 |
| 配置されてないと表示される | 内勤に連絡。/admin/assignments から配置追加してもらう |
| 過去の日報を見たい | /m/worker/reporting → 「過去の日報」 |
| パスワード忘れた | ログイン画面の「あいことば忘れた」 → メールでリセット |
